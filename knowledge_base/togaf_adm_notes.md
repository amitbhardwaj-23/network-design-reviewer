# TOGAF ADM Notes

## Phase A — Architecture Vision
Establishes the scope, constraints, and expectations for the architecture project.
Stakeholder concerns are identified and mapped. The Statement of Architecture Work is produced.
Security and compliance requirements must be captured at this phase.

## Phase B — Business Architecture
Documents the business strategy, governance, organisation, and key processes.
Business capabilities and value streams are mapped to identify gaps.

## Phase C — Information Systems Architecture
Covers both Data Architecture and Application Architecture.
Data governance, lineage, and classification must be addressed here.
API design standards and integration patterns are defined in this phase.

## Phase D — Technology Architecture
Maps technology components to application and data requirements.
Network, compute, storage, and security infrastructure are designed here.
Zero Trust architecture controls are applied at this phase.
Infrastructure standards and reference architectures are produced.

## Phase E — Opportunities and Solutions
Identifies delivery vehicles — projects, programmes, and portfolios.
Work packages are defined and prioritised based on business value and risk.

## Phase F — Migration Planning
Produces the Architecture Roadmap and Implementation and Migration Plan.
Transition architectures are defined for each major migration milestone.

## Phase G — Implementation Governance
Ensures conformance to the target architecture during delivery.
Architecture contracts, compliance reviews, and design authority oversight.
Change requests are assessed against the target architecture.

## Phase H — Architecture Change Management
Monitors the technology environment for changes requiring architecture updates.
Manages the process for handling architecture change requests.
Ensures the architecture remains fit for purpose as the environment evolves.
